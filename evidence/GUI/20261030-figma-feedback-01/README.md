## 구현 범위

- 기본 앱은 명시적인 `feedbackDemo: true` 프로필로 등록5대(연결4/끊김1), 오류/경고 각1건을 공급한다. UI 수치는 공급자에서 계산하며 5대로 고정하지 않는다.
- 선택 AMR의 출발/목적지 좌표·목적지 담당 AMR·거리·위치를 표시한다. 경로 선 없이 확대/축소/전체 보기를 제공한다.
- 같은 앱의 AMR별 별도 창에서 출발지 설정·시작·Stop·현재 상태·알람·응답을 제공한다. 기존 Simulator 계산을 재사용한다. 이 Mock은1.5m/s로 X축 후 Y축 이동하며 운영 경로 탐색/교통 제어가 아니다.
- 조회/통지는 IAmrDataProvider, 시작/Stop 접수는 ICommandDispatcher를 사용한다. 알람 등급·활성 여부·비고, Journey와 History를 선택적 데이터로 추가했다.
- 시작 수락과 도착 완료를 구분한다. Stop 후 재개/재시작은 제공하지 않는다. 창 닫힘은 해당 Mock 이동만 정지한다. 이 정책은 로컬 Mock 범위이며 실제 장비의 물리 정지를 뜻하지 않는다.
- 이력의 AMR·유형·기간 조건과 선택 초기화는 기록을 삭제하지 않는다. 이력은 앱 세션 메모리에 보관한다.
- 기존2대 Mock 대역·실제 `--grid-url` 모드·MQTT·보존 자료를 유지했다. 격자/MQTT 화면의 기존 경로 표시·미션 재개 계약은 이번 Mock UI 변경과 구분한다.

## 설계 판단과 한계

- 작은 Mock은 같은 잠금 안에서 상태·명령·이력 사본을 만들고 기존 비동기 통지 계약을 유지한다. UI 스레드의100ms 타이머가 단조 경과 시간을 전달하므로 별도 작업 스레드의 종료/경합을 늘리지 않았다. MainForm 종료 시 타이머·자식 창·구독을 정리하고 Program이 공급자를 정리한다.
- 별도 프로세스 Simulator는 더 강한 장애 격리를 제공하지만 IPC·프로세스 수명 관리가 추가된다. 현재 요청인 같은 앱의 별도 Mock 창에는 기존 계산 재사용이 단순하다. 실제 장비 연동 또는 대규모 AMR 운행 시에는 이 Mock 타이머/전체 사본을 운영 구조로 확대하지 말고 갱신 비용과 책임 경계를 재검토한다.
- 예상 검토 질문1: 수락은 완료인가? → 아니다. MOVE는 수락 직후Unconfirmed, 목표 도착 시Success다. Stop은 실제 ACK를 만들지 않고 Mock 정지를 기록한다.
- 예상 검토 질문2: 초기화하면 기록도 없어지는가? → 조회 조건과 행 선택만 초기화한다. 새 앱 실행은 별도 Mock 세션이므로 이전 메모리 기록을 복원하지 않는다.
- 예상 검토 질문3: Stop 후 다시 시작할 수 있는가? → 현재 Figma 검토 기준에서는 제공하지 않는다. 재시작/초기화·실제 장비 창 닫힘 정책은 후속 결정이 필요하다.
- 실제 MQTT Command/ACK·DB·운영 재시작 정책과 모든 DPI/다중 모니터 조합은 미검증이다. Figma의 글꼴/위젯은 WinForms 기본 위젯에 맞췄으며 픽셀 단위 일치를 완료조건으로 주장하지 않는다.

실행 방법은 [BUILDING](../../../BUILDING.md#windows-forms-mock-대시보드지도)을 따른다. 계획·업무 기록 원본 `C:\process-plan`은 이번 실행 확인에서 갱신하지 않았다.
