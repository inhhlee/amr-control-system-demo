- [기존 144파일의 원시 SHA256](file-manifest.json): 게시 전 작업 파일 목록. 빌드 생성물·개인 설정·문서 저장소 파일은 포함하지 않는다.
- [게시 검사 결과](verification.json): 현재 파일과 최종 시험본의 23파일 일치, TRX 집계, JSON/XML·로컬 근거 링크 검사 및 Git 게시 객체 대조 결과를 기록한다.
- Git은 소스·안내의 CRLF를 LF로 저장할 수 있다. 해당 차이는 스테이징 blob과 원시 파일을 별도로 비교한다. 과거 `evidence/GUI/` 파일은 원시 바이트로 스테이징해 로그·TRX·화면·기존 manifest의 원본을 보존한다. 저장소의 전역/공유 줄바꿈 설정은 변경하지 않는다.
- 현재 환경의 Git Flow는 AVH 1.12.3이고 기존 `main`/`develop`/`feature/` 설정을 재사용했다. 협업 문서의 git-flow-next 전용 상태 명령은 지원하지 않지만 `feature start`는 같은 develop 기준 브랜치를 생성했다. 기존 변경을 stash하거나 삭제하지 않았다.
- 최초 최종 검사에서 이번에 생성한 게시 JSON의 Windows CRLF가 공백 검사에 걸려 커밋 전에 중단됐다. 새 게시 JSON만 LF로 저장하도록 보완했으며 기존 144파일·제품/시험 소스는 변경하지 않았다.

## 설계·확인 범위

조회/명령 계약은 Core에 두고 GUI가 참조한다. Mock의 조회·명령 공급자는 같은 상태를 사용한다. 초기 캡처와 구독 등록·변경을 같은 잠금으로 처리하고 Revision으로 늦은 값 덮어쓰기를 막는다. 폼은 자기 구독/진행 작업을 취소·대기하며 공유 공급자는 시작 지점이 정리한다. 프로세스 내부 보장이며 실제 MQTT 전달 보장으로 확대하지 않는다. 이유·대안·예상 PR 질문과 검증 한계는 위 두 실행 README에 있다.

실제 Core 업무/MQTT/SQLite 연결, 알람·이력 전체 화면, STOP/RESET 업무 규칙, 격자·경로·장애물, 운영 부하·Visual Studio 디자이너 편집은 후속/미검증이다. 구독64·요청128은 Mock 개발 설정이다. 이번 완료 단계는 PR 생성까지이며 승인 리뷰·병합·Issue 종료는 후속이다.
