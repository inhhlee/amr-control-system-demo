## 설계 선택과 검토 질문

Map만 다시 그리는 작은 Control 하나를 루트에 둬 Marker·hit test·축 변환을 MainForm에서 분리했다. 요약은 현재 스냅샷에서 계산하고 공유 상태를 새로 만들지 않았다. 현실적인 대안은 별도 UserControl·Presenter로 모든 영역을 분리하거나 외부 지도 라이브러리를 도입하는 방식이다. 재사용/대규모 장면에는 유리하지만 현재 두 장비의 좌표 표시에는 파일·참조가 늘어난다. 장비 수·갱신 빈도·배경 도면·줌/이동 요구가 늘 때 측정 후 분리/라이브러리를 검토한다. 대안 성능 시험은 하지 않았다.

1. **예시 경로가 왜 없는가?** 현재 공급자에는 경로/장애물 자료가 없다. 가짜 이동/목표를 만드는 대신 출처·자료 없음으로 표시했다.
2. **연결 끊김이 오류 운행 수를 늘리는가?** 아니다. Broker/생존 관측과 State를 각각 집계하고 Marker 점선 관측도 분리했다.
3. **창 변경/닫기에서 기존 수명을 유지하는가?** UI 반영은 기존 InvokeAsync, 선택 요청/Revision 보호와 모든 진행 작업 대기를 유지했다. 폼은 공유 공급자 전체를 종료하지 않는다.
