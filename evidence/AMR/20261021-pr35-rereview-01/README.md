## 2. P2 수정과 회귀시험 대조

`SimulatorSettingsLoader.cs:20`에서 바이트로 읽고, 맨 앞 UTF-8 BOM만 제외한 뒤 `UTF8Encoding(false, true)`로 해석한다. StreamReader의 BOM 자동 감지에 디코더 선택을 맡기는 이전 경로가 제거됐다. 잘못된 바이트는 기존 `ConfigurationException($file, 인코딩 오류 이유)`로 전달된다.

Application은 로더 성공 후에만 AMR을 생성한다. 로더의 예외와 Application의 반환 코드 1·빈 stdout·정확한 stderr를 각각 검사하므로, 성공 로그가 없다는 관찰만으로 생성 전 거부를 판단한 것은 아니다.

## 5. 설계·수명 검토와 남은 한계

- 전체 바이트 배열 추가에 따른 메모리 비용은 문서에 명시돼 있다. 현재 설정 범위에서 결함으로 판단하지 않는다. 대규모 파일 요구가 생기면 엄격한 StreamReader 방식과 비교할 수 있으나 이번에 성능·메모리 벤치마크를 수행한 것은 아니다.
- 실제 키보드 Ctrl+C, NuGet 취약성 조회, 전체 솔루션·기존 통신 회귀의 새 실행, 사용자 직접 확인·사람 승인, 계획·일일업무 원본 반영은 남아 있다. 이동·실행 루프·MQTT·GUI는 이번 #32 범위 밖이다.
- 가능한 모든 UTF-8 오류·모든 파일 크기 조건을 전수 검증한 결과로 확대하지 않는다.
