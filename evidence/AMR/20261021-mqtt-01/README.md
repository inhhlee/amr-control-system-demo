## 구현과 선택 이유

- `src/Amr.Simulator/Telemetry/`에 옵션 검사·메시지 생성·MQTT 전송·실행 수명 관리를 추가하고 기존 Communication 프로젝트를 참조했다. 새 NuGet 버전은 추가하지 않았다. MQTT 옵션이 없으면 기존 독립 이동 흐름이다.
- 실행 루프가 **불변 위치 복사본**을 만들고 송신 루프는 최신 복사본 하나를 읽는다. 이동 모델의 좌표·속도·상태를 송신 스레드에서 따로 읽지 않아 서로 다른 시점이 섞이지 않는다. 네트워크 대기가 이동 계산을 막지 않는다.
- 위치와 Heartbeat의 주기는 별도 명시한다. 이번 200ms/1000ms는 시연 입력이며 운영 주기 확정이 아니다. 초기 Telemetry·Heartbeat와 최종 Telemetry는 주기와 별도로 전송한다. 이동 완료 후 연결을 닫는 1회 시나리오이며 도착 후 상시 Heartbeat 서비스는 후속이다.
- 오래된 위치를 큐에 쌓지 않는다. 느린 전송에서 중간 샘플은 생략될 수 있고 지연된 주기를 몰아서 재전송하지 않는다. 전체 이동 샘플 기록이 필요하면 별도의 저장·용량·전달 보장 설계가 필요하다.
- MQTT 5·QoS0·Retain=false·CleanStart·새 Client ID·SessionExpiry0을 사용한다. 송신/접속/해제 제한은 개발용 3초이며 OS 스케줄링을 포함한 실시간 보장은 아니다. 재시도·자동 재접속·Exactly-once를 추가하지 않았다.
- 한 세션이 이동 Task·송신 Task·취소·Client를 소유한다. 실패/취소 시 양쪽 작업의 실제 종료를 기다리고 이벤트 해제·연결 해제·Dispose를 수행한다. 사용자 취소·단절·오류·최종 발행 완료 중 먼저 확정된 결과를 유지한다. 완료 뒤 늦은 취소가 성공을 취소로 바꾸지 않는 시험도 추가했다.

대안: 이동 계산마다 네트워크 송신을 기다리는 방식은 단순하지만 느린 네트워크가 이동 갱신을 막는다. 매 이동점 큐 방식은 전건 보존에 유리하나 메모리·과부하·종료 시 폐기 정책이 필요하다. 이번에는 최신 위치를 보여 주는 한 대 시연 목적에 맞춰 불변 복사본 하나와 독립 주기를 선택했다. 관제 코드는 기존 검사·AMR별 큐·수신 출력을 그대로 사용했다.

예상 리뷰 질문과 근거:

1. **실제 좌표인가?** 이동 루프 복사본으로 생성하며, 실제 32개 수신 위치를 실행 로그와 대조했다. 브라우저가 만든 좌표가 아니다.
2. **Heartbeat와 State는 같은가?** Heartbeat의 status=OK는 실행 신호다. 운행 상태·현재 속도는 Telemetry의 state/sp이며 BUSY/IDLE을 보존한다. 최종 Offline 판정은 별도다.
3. **종료할 때 송신 작업이 남는가?** 단일 소유자가 두 Task를 기다린다. 느린 송신 취소·발행 실패·해제 실패·늦은 취소를 자동시험으로, 실제 Ctrl+C·Broker 종료를 프로세스 시험으로 확인했다. 전원 차단·비협조적 외부 라이브러리의 무한 정지는 미검증이다.

## 이력과 남은 범위

- 최초 빌드는 기존 NuGet 잠금 파일 접근 권한으로 실패했다([build-01](build-01.log)). 잠금 파일을 삭제하지 않고 이번 빌드 프로세스만 확인해 종료한 뒤 정상 사용자 권한으로 재실행했다.
- 첫 자동시험149건·[실제 실행01](../20261021-mqtt-live-01/verification.json)은 통과했다. 종료 경계의 늦은 취소 처리와 해제 실패 검증을 보완하여 최종151건·실제 실행02를 수행했다. 두 실행의 건수와 시간은 합산하지 않는다.
- 기존 통신 소스는 변경하지 않았다. 통신 자동시험 전체·MQTT Explorer GUI·Seq·물리 장비·다중 사용자·운영 부하는 이번에 재실행하지 않았다.
- 남은 기능: MQTT로 받은 좌표의 지도 표시, 다중 AMR, 명령 수행·ACK 대조, Alarm·자동 재접속·장애 복구, Core·DB·전체 통합 시험. 1번의 수신 콘솔까지 완료했으며 과제 전체 완료가 아니다.
- 기존 변경·Git 인덱스·HEAD·브랜치를 유지했다. 커밋·푸시·PR·병합·Issue 변경은 하지 않았다.
- 기존 파일 935개의 해시가 동일했다. 이번 변경을 합친 기존 SimulatorApplication·SimulationRunner와 README는 별도로 구분했다. 실행 중인 기존 지도 서버의 로그 2개는 잠금으로 시작 해시를 읽지 못해 동일 판정에서 제외했으며 이 작업이 쓰거나 삭제하지 않았다. 정식 과제계획의 전체 상태 정리는 별도 후속이고 이번 현재 실적은 결과 문서와 같은 날짜 일일업무에 연결한다.
