# 실제 시뮬레이터 좌표와 연결한 2D 지도 — 구현·시연 결과

**지도에서 출발 → 경유점 → 목적지 이동을 확인했고, 실제 시뮬레이터 로그와 지도 좌표가 일치했다.** 현재 지도 서버와 브라우저를 시연용으로 열어 두었다. 임시 주소는 [http://127.0.0.1:65006](http://127.0.0.1:65006)이며 서버가 종료되면 사용할 수 없다. 재실행 방법은 [지도 시연 안내](../../../tools/Amr.Simulator.Map/README.md)를 따른다.

![실제 이동 후 도착·정지 화면](map-final.jpg)

## 무엇이 바뀌었나

- 새 `tools/Amr.Simulator.Map` 프로젝트에 로컬 웹 서버와 2D 좌표 화면을 추가했다. 출발점·경유점·목적지, 실제 AMR 위치, 좌표·속도·상태·경과 시간·종료 코드를 표시한다.
- **시연 시작 / 다시 실행**은 현재 콘솔과 같은 `SimulatorApplication.RunAsync`를 서버 프로세스 안에서 실제 실행한다. 동일한 설정 로더·이동 계산·실행 루프·단조 시계를 사용한다. 미리 만든 좌표 배열이나 브라우저 애니메이션으로 이동을 흉내 내지 않는다.
- **실행 취소**는 실제 실행의 CancellationToken을 취소한다. 도착 완료와 별도로 표시하며, 마지막 계산 위치를 유지한다. 실제 로봇 STOP 명령과 구분한다.
- 지도 경로와 실행 입력은 서버 시작 시 만든 같은 설정 복사본을 사용한다. 원래 설정·제품 소스는 보존했다. 최종 확인에서 솔루션에 지도 프로젝트가 추가 등록된 변경도 발견하여 그대로 유지했다. 새 패키지는 추가하지 않았다.
- 이번 범위는 사용자가 추가 요청한 단일 AMR 시연 도구다. 과제3 전체 GUI·MQTT 연동 완료로 확대하지 않는다. 커밋·푸시·브랜치 전환·Issue/PR 변경은 하지 않았다.

## 설계 이유·수명·대안

새 Web 프로젝트가 기존 Simulator를 참조하고 `RunAsync`의 TextWriter만 연결한다. 계산을 복제하지 않아 콘솔과 지도가 같은 동작을 사용하며, 기존 콘솔 동작과 출력 계약도 보존한다. 별도 프로세스 stdout을 수집하는 대안은 장애 격리에 유리하지만 실행 파일 위치·프로세스 제어·취소 전달이 더 필요하다. 이번 한 대 시연에는 같은 프로세스 호출을 선택했다. 운영용 격리 또는 여러 시뮬레이터를 동시에 실행해야 하면 별도 프로세스나 형식 있는 이벤트 계약을 검토한다.

`MapSession`은 실행 Task·취소 토큰·상태·출력 파일을 소유한다. 한 실행만 허용하고, 짧은 lock 구간에서 상태를 갱신·복사한다. 취소 요청과 종료 완료를 구분하며 기존 Task가 끝나기 전 새 실행은409로 거절한다. 서버 종료 시 취소 후 Task를 await하고 토큰을 정리한다. 화면의 최근 로그는 80줄로 제한하고 전체 로그는 실행별 파일에 저장한다. 로그 파일은 자동 삭제하지 않으므로 장기간 반복 시 저장 공간은 사용자가 관리해야 한다.

로컬 127.0.0.1에만 바인딩하고 시작·취소 POST에 전용 헤더를 요구한다. 외부 서비스·계정·Broker를 사용하지 않는다. SSE/WebSocket 대신 100ms 최신 상태 조회를 택해 브라우저 재접속과 서버 자원 관리를 단순하게 했다. 고빈도·대규모 전송에는 낭비가 있으므로 여러 AMR·많은 사용자가 필요하면 전송 방식을 다시 정해야 한다.

예상 리뷰 질문:

- **브라우저가 자체적으로 점을 움직이는가?** 아니다. 실제 출력의 X/Y를 API→SVG로 전달한다. HTTP 표본141개와 브라우저 DOM·로그 대조를 근거로 한다.
- **취소 후 실행이 뒤에 남는가?** Task·토큰을 단일 MapSession이 소유한다. 실제 취소·재실행 및 서버 종료 중의 취소/종료/포트 해제를 확인했다. 강제 종료·전원 차단은 검증 범위 밖이다.
- **이 화면으로 관제 GUI가 완료됐는가?** 단일 AMR 시연 도구다. MQTT·명령·다중 AMR·지도 편집·장애물·실제 장비·운영 인증·장시간 부하는 후속이다.

## 실패·한계·남은 상태

- 최초 빌드는 샌드박스 계정의 NuGet 잠금 파일 접근 제한으로 실패했다([원본](build-01.log)). 잠금 파일이나 설정을 삭제하지 않고 승인된 일반 사용자 권한으로 다시 빌드해 성공했다.
- 브라우저에서 한 번의 완료 대기는 도구 기본 제한이 약3초여서 약4초 시연보다 먼저 끝났다. 이어진 DOM 확인에서 실제 완료를 확인했으며 제품 오류로 집계하지 않는다. 브라우저 콘솔의 오류·경고는 조회 시 없었다.
- 기본 경로와 변경 경로를 실제 검증했다. 모든 double 좌표 범위·대규모 경유점·다중 사용자·장시간 운영은 미검증이다. 유한 범위 계산이 불가능한 지도는 표시 불가 안내를 하며 제품 입력 계약 자체를 바꾸지 않는다.
- 현재 열린 지도 서버(PID는 server-process.json)는 사용자 시연을 위해 유지한다. 자동 감시나 백그라운드 반복 실행은 하지 않는다. 별도 변경 경로 검증 서버는 종료·포트 해제를 확인했다.
- 정식 Git 브랜치/PR 정리·리뷰·반영은 후속이다. 커밋·푸시는 하지 않았다.
