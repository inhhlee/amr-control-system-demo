# 지도 시연 설정

이 폴더의 **settings.json**만 편집하면 코드 변경·재빌드 없이 지도와 이동 조건을 바꿀 수 있다. JSON은 UTF-8로 저장한다. 현재 시연과 같은 5×6 지도·W1→W2→G·MQTT 접속값이 들어 있다.

| 항목 | 변경 방법 |
| --- | --- |
| `amrId` | AMR 이름. 같은 Broker에서 다른 송신 프로그램과 중복되지 않게 지정한다. |
| `map` | 0=통로, 1=고정 장애물. 모든 행의 칸 수를 같게 한다. 행·열 수도 바꿀 수 있다. |
| `start` | 출발점 `(row, col)`. 좌상단은 `(0,0)`이다. |
| `waypoints` | 위에서 아래로 방문한다. 마지막 좌표가 목적지 G다. 맵 안의 통로에 하나 이상 지정한다. |
| `stepIntervalMs` | 한 칸 이동 간격(ms). 600=0.6초, 1000=1초. 양의 정수. 작은 값은 실행·통신 지연의 영향을 받는다. |
| `webPort` | 지도 주소의 포트. 기본 주소는 `http://127.0.0.1:59344/`. 0이면 빈 포트를 자동 선택한다. |
| `mqtt.enabled` | `true`이면 MQTT로 보내고 관제 수신 좌표를 표시한다. `false`이면 계산 위치를 직접 표시한다. |
| `mqtt.host` / `mqtt.port` | Broker 주소·포트. 기본값은 기존 로컬 Broker `127.0.0.1:1884`. |
| `mqtt.telemetryMs` / `mqtt.heartbeatMs` | 위치·상태와 Heartbeat의 송신 간격(ms). 각각 양의 정수. |

1. 실행 중인 지도 서버를 종료한다.
2. `settings.json`을 수정하고 저장한다.
3. 저장소 루트에서 `dotnet run --no-build --project tools/Amr.Simulator.Map`으로 다시 실행한다.
4. 출력된 지도 주소를 열고 **출발**을 누른다.

처음 빌드할 때는 `--no-build`를 생략한다. 설정은 **서버 시작 때 한 번 읽는다**. 브라우저 새로고침이나 **원래 지도로 초기화**만으로 파일 변경을 읽지 않는다. 화면에서 추가한 장애물은 파일에 저장하지 않으며 초기화하면 이 파일의 지도로 돌아온다. MQTT Broker는 별도로 실행되어 있어야 한다.

잘못된 지도·벽 위의 좌표·빈 경유점·0 이하 주기·잘못된 포트·필드 오타는 서버 시작 전에 오류로 알린다. 경로가 완전히 막힌 지도 자체는 허용하며 실행 시 길이 열릴 때까지 기다린다.

폴더를 복사해 다른 시나리오를 보관할 수 있다. `--config config/다른폴더/settings.json` 또는 절대 경로로 선택한다. `--port`는 파일의 `webPort`보다 우선한다. 기존 MQTT 명령행 옵션 4개를 모두 지정하면 파일의 MQTT 설정보다 우선한다. 명령행 옵션 없이 실행하면 파일의 값만 사용한다.

1칸=1m, MQTT X=열·Y=-행은 현재 시연의 고정 좌표 규칙이다. 기존 `config/simulator.grid.json`은 이전 경유점 전용 형식의 호환용 입력이며, 현재 기본 설정은 이 폴더의 파일이다. 제품 콘솔용 `config/simulator.single.json`은 별도로 유지한다.
